# 核查博客现状与 GitHub 同步状态

## Goal

只读核查博客本地工作区与 GitHub 远程是否一致，并盘点博客当前运行、发布与内容现状，产出可核对报告。

## Requirements

1. **GitHub 同步核查**：本地分支与 HEAD、工作区状态；远程 origin 默认分支与最新提交；本地相对远程的 ahead/behind 数量与未推送提交清单；本地与远程标签差异；GitHub Releases 版本清单与最新版本。
2. **发布对账**：v0.0.29 Release 资产名、字节数、sha256 与本地 `dist/` 比对；本地发布包、tag、Release 是否互相对应。
3. **博客运行现状**：`nobelog-local.service` 状态、启动时间、监听端口、运行模式与仓库根；运行二进制版本与 sha256；运行二进制与当前源码提交的关系。
4. **内容与配置**：文章、页面、图片数量；站点域名与标题配置；`SITE_URL` 现状；Rust 工具链版本；`public/` 冻结基准与 `dist/` 目录现状。
5. **偏差与风险清单**：未推送提交、仅本机缺失的发布包、运行服务与工作区版本差异、未授权不探测的外部博客域名。
6. **报告落盘**：写入 `.trellis/tasks/10-30-audit-sync-github/research/sync-audit.md`，含命令、原始输出摘要、事实表与明确结论。

## Acceptance Criteria

- [ ] 报告明确回答工作区与 GitHub 是否一致；若不一致，列出 ahead/behind 数量与逐条提交。
- [ ] 报告给出本地标签、远程标签、GitHub Releases 三方对账结果。
- [ ] 报告给出 v0.0.29 本地包与远程资产的字节数与 sha256 比对结果。
- [ ] 报告给出运行服务、运行二进制、源码提交三者的关系判断。
- [ ] 报告给出博客内容规模与配置概览，并列出偏差与风险。
- [ ] 全部核查只读：除 research 报告外无任何文件改动，无 git 写操作。

## Constraints

- 只读调查；禁止 `git commit` / `push` / `fetch` / `reset` / `checkout` 等写操作；远程信息用 `git ls-remote` 与 `gh` 只读查询。
- 不访问未授权的公网博客域名；授权范围为本地仓库、本地服务与 GitHub `zhemed/nobelog`。
- 不重启服务、不多开实例、不安装任何东西。
- 报告写入任务 `research/` 目录，交由 Lead 复核后归档。
